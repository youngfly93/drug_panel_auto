## 二、判定：🟡 中等，高度复用 CRC 引擎

| 区域 | 与 CRC | 处理方式 |
|---|---|---|
| Part3 逐变异解析、2.1变异表、2.2/2.3、TMB、MSI、免疫正负超、参考文献、签名 | **完全共享** | CRC 流水线按 Excel+KB 自动填（endometrial 已实证）|
| **3.2 PD-L1 表达** | CRC 无 | **表单标量 + 展示节 + 分档解读**（小，见三）|
| 4.x NSCLC 化疗 | 内容不同·结构同 | 静态变量化（一次性）|
| 附录 a.EGFR/b.ALK/c.ROS1 肺癌知识、2.3 肺NCCN表、329基因列表 | 内容不同·结构同 | 静态变量化（一次性）|

> **纠正记忆误读**：lung Part3 **不是**按 a.EGFR/b.ALK 分组——那个分组在**附录的肺癌
> 诊疗知识**里；Part3 与 CRC 同款逐变异解析。且 lung 同时有 PD-L1 **和** MSI（PD-L1 作为
> 3.2 插入，MSI 顺延到 3.3），不是"PD-L1 而非 MSI"。这与 lung329-onboarding 早期记的
> "cousin 83%" 一致——lung 本就高度 CRC 化。

## 三、PD-L1 = 表单标量，不是新引擎（关键）

- **共用 Excel 内不含 PD-L1/TPS/CPS**（PD-L1 是 IHC 结果，独立录入）。
- 现有 MVP 已把 `pdl1_tps`/`pdl1_cps`/`pdl1_result` 变量化为标量。
- 所以 PD-L1 模块 = 3 个表单标量 + 3.2 展示节 + 高/低分档解读文案（≥50% / 1–49% / <1%）。
  **不需要 NGS 分析逻辑**，体量小。

## 四、现有 MVP 是"错的形状"，C-beta 要重做金标模板

现 MVP 模板：仅变量化标量，**无 `__PART3_MARKER__`、无表循环**，逐变异/变异表/药物全
"中和留空"。这形状**接不上 CRC 流水线的自动填充**。C-beta 正确做法 = **像 crc_301 那样
把一份真实 lung 终版完整变量化**：

1. **重做 lung 金标模板**：加 `__PART3_MARKER__` + 变异表 `{%tr%}` 循环 → CRC 流水线自动
   填变异/药物/Part3。**主要工作量**（这正是 crc_301 成功做过的事）。
2. **PD-L1 3.2 节**：接 pdl1_* 标量 + 分档解读文案。**小**。
3. **肺静态内容**：NSCLC 化疗 4.x、附录肺癌知识、肺 NCCN 表、329 基因列表 变量化进模板。
   **一次性静态**。
4. **合成 lung Excel 测试数据**：扩 `scripts/gen_endometrial_test_excels.py`（PD-L1 走表单，
   只需变异 + 标志物）。
5. **合成 golden case + 样式基线**（baselines/lung_329_pdl1_*.json）+ 报告组真实样本签收 + 部署。

**工作量**：> endometrial B 档 pilot，< 从零大工程。≈ 一次 crc_301 式 A 档金标迁移 + PD-L1
标量节 + 肺静态内容。两步变量化工具链 + CRC 引擎复用。

## 五、"带一批" 成立

PD-L1 是**跨癌种模块**：语料里 CRC 733/1350、膀胱66、泛癌种1350 都带 +pd-l1，胃/食管/
头颈/胆管大概率同款。**PD-L1 节做一次 → 这一批都能加**；lung 家族（62/158基因…）同结构、
recipe 复用。
