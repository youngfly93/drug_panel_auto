## 1. 决策与边界

本轮上线对象为独立产品 `lung_588_pdl1`，不是现有草案
`lung_329_pdl1` 的改名版本。

- 保留 `lung_329_pdl1` 为未上线草案，不修改其 329 基因覆盖分母。
- 从 CRC 与肺癌329工作中复用通用映射、渲染、QA 和发布能力。
- 肺癌588的基因分母、筛选规则、药物规则、知识覆盖、模板和 UAT
  全部独立治理。
- 真实 Excel、历史 Word、患者信息、签名和生成报告只作为本地受控输入，
  不进入 Git；仓库只保存脱敏别名、SHA256、结构化期望和审核状态。
- 在受控试运行门禁完成前，Panel 与默认模板保持生产禁用；进入试运行后
  生命周期为 `pilot`。只有正式真实病例UAT和方法学确认完成后才能改为
  `active`。
- 报告组当前只能提供 3 份真实肺588输入，因此增加一个不冒充正式 UAT 的
  `controlled_internal_pilot` 层：3份真实病例验证实际输入与历史金标，
  7份脱敏合成病例验证边界、分页和串漏。10份真实病例要求保留为
  `active` 正式发布门禁，不因合成件而降低。
- 受控试运行只允许逐病例转录原始PD-L1记录。若来源没有说明抗体克隆和平台，
  报告必须明确显示“未提供”，不得套用22C3阈值、推断方案等效性或生成患者级
  用药资格结论。

## 5. 分阶段实施

### Phase A：产品身份与输入门禁

1. 修复全局 `project_info` 污染项目识别。
2. 新建 `lung_588_pdl1` 草案包、别名、588 基因清单和输入合同。
3. 单份手工选择优先于自动识别，并在任务快照中留痕。
4. PD-L1 三字段做范围、一致性和缺失阻断。
5. 批量在支持逐文件 PD-L1 载荷前显式阻断，不允许共享一组值。
6. 模板不得携带静态 PD-L1 病例图像；图像、抗体克隆和检测平台必须逐病例可追溯，
   或在受控pilot中明确显示“原始记录未提供”，并禁止治疗推断；active前仍须完成
   实际方法学确认。
7. PD-L1结果必须绑定经二审启用的检测方案和逐病例原始IHC记录；没有运行
   方案时不得仅凭TPS/CPS/高低分层生成交付报告。受控pilot的旧记录转录方案
   不执行阈值推导，也不得从数值推导患者级用药。

### Phase B：结构化结果与金标准

1. 将肺癌显式Ⅰ/Ⅱ/Ⅲ类筛选做成 Panel 规则。
2. 固化 CASE-LUNG-B/C 的变异、TMB、MSI、PD-L1 exact diff。
3. 补 CNV、融合、HLA、阴性结果和复合表边界测试。

### Phase C：知识和医学规则

1. 先盘点两个金标准实际命中的精确事件，并将可追溯条目保存为
   非运行时候选。
2. 每条规则必须包含癌种、事件类型、方向、证据等级、来源和审核状态。
3. 未审核条目不得进入运行规则；知识缺口必须进入 QA。
4. 分开统计588基因基础覆盖、肺癌特异覆盖和二审覆盖。
5. 候选只有在报告组逐事件二审、当前标签/指南版本核对、正反例测试和
   病例 UAT 后，才能另行迁移至 `rules/drugs.yaml`；候选文件本身永不
   作为运行时来源。
6. 药物候选还必须按事件校验肺癌病理类型、疾病范围、既往系统治疗和
   伴随诊断适配状态；缺失、`未明确` 或 `待确认` 时失败关闭。
7. 每条候选必须附逐来源“支持/不支持”边界，并分别记录直接精确事件疗效、
   功能证据、监管类别和伴随诊断证据；没有精确位点疗效亚组时必须显式写明，
   不得以证据链拼接冒充直接临床结果。

### Phase D：Word 与视觉 QA

1. 从历史终版保留样式，去除病例值、调试残留、损坏关系和旧生成字段。
2. 表格使用结构化循环，Part3 使用动态 marker。
3. PD-L1 页面验证“无静态病例图像”；若展示图像，必须验证该病例资源身份。
4. 在 Linux LibreOffice 下检查目录、分页、空白页、表格宽度、签名和页码。

### Phase E：UAT 与部署

1. 受控试运行：3份已确认真实肺588输入全部通过，并包含两个历史金标准；
   另以7份固定脱敏合成病例覆盖PD-L1显示、MSI/TMB、精确事件反例、长表分页
   和串病例检查。合成件只计工程覆盖，不计真实病例UAT。
2. 受控试运行通过率必须为100%；P0、串病例、错 Panel、关键结果错误均为0。
   批量、第三部分知识、靶向药物规则继续关闭，下载交付必须人工复核。
3. 正式 `active`：累计至少10份脱敏真实病例，总通过率不低于90%，并补齐
   实际PD-L1方案方法学确认；该要求不因试运行通过而自动满足。
4. 冻结 commit，自审固定身份，运行对应层级发布总闸。
5. 以 immutable release 部署 iyun129，验证健康检查、单份、
   下载、任务恢复和版本回滚；肺588批量仍应被明确阻断。

## 6. 发布状态定义

- `ENGINEERING_DRAFT`：包可加载，规则默认关闭，不允许交付。
