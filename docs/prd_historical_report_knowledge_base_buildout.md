# 历史终版报告知识库建设 PRD

版本：v0.1
日期：2026-06-06
状态：Draft
作者：Codex

## 1. 背景

当前报告自动化系统已经具备 CRC358/301 等报告生成能力，并已开始通过
`reviewed_part3_knowledge.yaml` 补充 Part3「基因简介 / 基因变异解析 / 药物关联分析」
的人工审核内容。

报告组反馈“知识库构建完成度不足 5%”，这个判断在“近几年历史终版报告是否系统性入库”
这个口径下是成立的：目前已补的是少量高优先级反馈位点和部分旧库内容，还没有把近年终版
报告中的人工解读内容批量结构化、审核、入库。

本 PRD 的目标是定义一套可落地的历史报告知识库建设流程，把本地历史终版报告语料转化为
可审核、可追踪、可量化覆盖率的正式知识库。

## 3. 问题定义

### 3.1 当前问题

1. Part3 解读覆盖不足，缺内容时会回退到基础库通用话术。
2. 历史终版报告里的人工审核文本尚未系统入库。
3. 现有补库更多是按反馈点手工修复，缺少批量候选生成、审核、入库、覆盖率复测闭环。
4. 不同癌种、不同 panel 规模的报告结构差异大，不能简单把一个癌种目录整体当作一个知识库来源。
5. 历史报告包含真实患者信息，任何抽取、留痕、导出都必须去标识化。

### 3.2 不解决会带来的风险

1. 自动化报告能生成，但 Part3 仍可能被报告组认为“像固定套话”。
2. 报告组每次只能靠截图反馈，问题无法规模化收敛。
3. 压测只能证明系统跑得通，不能证明报告内容达到生产可用。
4. 新 panel 接入会重复遇到同样的知识库缺口。

## 4. 产品目标

### 4.1 P0 目标

1. 对历史终版报告做去标识化索引，形成可复跑的语料清单。
2. 从终版报告中抽取候选知识内容：
   - 基因简介
   - 基因变异说明
   - 基因变异解析
   - 靶向药物获益/耐药/慎用段落
   - 免疫治疗相关段落
   - 参考文献 PMID
3. 按 `癌种 / 产品族 / 基因 / 位点 / 内容类型` 去重归并。
4. 输出报告组审核表，支持“通过 / 修改后通过 / 不通过 / 暂缓”。
5. 只有审核通过内容才能进入正式知识库。
6. 每次入库后自动输出覆盖率报告，量化“仍有多少通用话术”。

### 4.2 P1 目标

1. 按优先级接入主力产品族：
   - CRC 大 panel：CRC358/301/733/208/166
   - 肺癌大 panel：肺329/588/158
   - 肺癌小 panel：肺13/20/62/66
   - 子宫内膜 29 基因
   - 卵巢/妇科相关 panel
2. 建立知识库版本号和来源追踪。
3. 在报告生成摘要和 QA 中显示 Part3 覆盖级别：
   - 位点级 reviewed
   - 基因级 reviewed
   - 基础库自动拼接
   - 基础库通用内容
   - 缺失

### 4.3 非目标

1. 不自动发明医学结论。
2. 不把未经报告组审核的历史文本直接用于生产。
3. 不把真实患者姓名、样本号、报告编号写入知识库。
4. 不要求一次性补满 358 个基因和所有可能位点。
5. 不在本阶段建设完整 LIMS 或登录权限体系。

## 5. 范围与优先级

### 第一阶段：CRC 生产缺口闭环

输入：

- 当前 CRC358 压测 Excel
- `各癌种基因报告近年汇总/肠癌`
- 已有 CRC reviewed overlay

目标：

- 优先消化当前压测剩余通用话术缺口。
- P1 缺口先处理 ERBB2、KMT2A 等高风险/高频基因或位点。
- 建立报告组审核表和入库脚本闭环。

验收：

- 当前压测批次 Part3 通用话术数下降到可接受阈值。
- 所有新增内容有审核结论。
- 至少 5-10 份真实报告人工 UAT 通过。

### 第二阶段：肺癌知识库补库

输入：

- `各癌种基因报告近年汇总/肺癌`
- 现有 `scripts/harvest_lung_part3_knowledge.py`
- 肺329/肺13/肺62 等产品族文件名分组

目标：

- 先按产品族拆分，不混跑整个肺癌目录。
- 肺329 等大 panel 优先复用大 panel 结构。
- 肺13/20/62/66 建立小靶向 panel 的独立知识库补库策略。

验收：

- 肺癌高频驱动基因不再回退 CRC 或泛癌种不适配话术。
- EGFR/ALK/ROS1/BRAF/MET/RET/ERBB2/KRAS 等重点基因有 reviewed 覆盖。

### 第三阶段：子宫内膜与妇科

输入：

- `各癌种基因报告近年汇总/妇科肿瘤-子宫内膜癌`
- `各癌种基因报告近年汇总/妇科肿瘤-卵巢癌`

目标：

- 子宫内膜重点补“分子分型、遗传风险、林奇综合征/错配修复”相关内容。
- 卵巢重点补 HRD、BRCA、同源重组修复、PARP 相关内容。

验收：

- B 档 pilot 可编辑样板不再只依赖静态占位。
- 关键章节能从审核知识库派生内容。

## 6. 知识库数据模型

建议候选库字段：

| 字段 | 说明 |
|---|---|
| `candidate_id` | 候选内容稳定 ID |
| `source_family` | 癌种目录，如 `肠癌`、`肺癌` |
| `product_family` | 产品族，如 `crc_358_msi`、`lung_329_pdl1` |
| `source_report_hash` | 原报告去标识 hash，不存真实文件名 |
| `gene` | 基因 |
| `c_hgvs` | c. 位点，可空 |
| `p_hgvs` | p. 位点，可空 |
| `variant_type` | 错义、无义、剪接、扩增等 |
| `content_type` | `gene_intro` / `mutation_analysis` / `drug_benefit` / `drug_caution` / `immune` / `reference` |
| `content` | 去标识后的候选文本 |
| `pmids` | 文献 PMID 列表 |
| `evidence_scope` | 位点级 / 基因级 / 癌种级 / 泛癌种 |
| `review_status` | 待审核 / 通过 / 修改后通过 / 不通过 / 暂缓 |
| `reviewer` | 审核者，可用角色或内部 ID，不必存真实姓名 |
| `reviewed_at` | 审核时间 |
| `promoted_to` | 入库目标文件 |
| `notes` | 审核备注 |

正式生产 overlay 仍使用 panel 规则包，例如：

```text
panels/<panel_id>/rules/reviewed_part3_knowledge.yaml
```

## 7. 流程设计

```text
历史 DOCX 语料
  ↓
去标识化索引 manifest
  ↓
DOCX 文本 / 表格 / 章节抽取
  ↓
基因、位点、药物、PMID 识别
  ↓
候选内容去重归并
  ↓
报告组审核 Excel
  ↓
审核通过内容转正式 YAML overlay
  ↓
生成压测报告
  ↓
覆盖率审计 + 人工 UAT
```

## 8. 去标识与安全要求

1. 原始 DOCX 不进入 Git。
2. 所有候选输出默认放在 `tmp/` 或明确 gitignored 的目录。
3. 候选表不保留患者姓名、样本号、报告编号、医院号、收样日期等标识信息。
4. `source_report_hash` 使用文件内容或相对路径 hash，不暴露真实文件名。
5. 日志不打印原文长段落，只打印候选数量、覆盖率、错误类型。
6. 入库前执行硬编码扫描，禁止真实患者字段进入 YAML。

## 9. 覆盖率指标

每轮补库必须输出以下指标：

| 指标 | 说明 |
|---|---|
| `reports_scanned` | 扫描历史报告数量 |
| `candidates_extracted` | 候选条目数 |
| `candidates_after_dedup` | 去重后条目数 |
| `approved_candidates` | 审核通过条目数 |
| `promoted_entries` | 入正式库条目数 |
| `site_level_reviewed_rate` | 位点级 reviewed 覆盖率 |
| `gene_level_reviewed_rate` | 基因级 reviewed 覆盖率 |
| `generic_fallback_count` | 基础库通用话术数量 |
| `missing_count` | 完全缺失数量 |
| `uat_pass_rate` | 报告组人工抽查通过率 |

生产前建议阈值：

- 当前生产批次 `generic_fallback_count` 明确列出并经报告组确认可接受。
- P0/P1 高风险候选必须处理完，不能只标记“以后补”。
- 抽查报告 UAT 通过率达到 90% 以上，再进入更大批量压测。

## 10. 功能需求

### P0：语料 inventory

系统必须能扫描历史报告目录，输出：

- 癌种目录分布
- 产品族分布
- DOCX 数量
- 无效文件数量，例如 `._*`
- 可能重复报告数量
- 可解析 / 不可解析数量

### P0：候选抽取

系统必须从 DOCX 中抽取：

- Part3 逐变异解析段落
- 药物获益/耐药/慎用段落
- 基因简介段落
- PMID 文献

抽取失败时必须记录失败原因，不得静默跳过。

### P0：审核表生成

系统必须生成报告组可读 Excel：

- 每行一个候选内容。
- 明确建议审核动作。
- 给出来源范围：位点级 / 基因级 / 癌种级。
- 默认审核状态为“待审核”。

### P0：审核结果入库

系统必须只读取审核状态为“通过”或“修改后通过”的内容。

入库前必须检查：

- 无患者标识。
- 无样本号。
- 无报告日期。
- 无明显模板占位残留。
- 无癌种错配，例如肺癌 overlay 中出现结直肠癌专属结论。

### P0：覆盖率复测

每次入库后必须对目标压测 Excel 执行覆盖率复测，输出：

- 覆盖分层统计
- 剩余缺口清单
- 高优先级补库建议

## 12. 验收标准

### 工程验收

1. 脚本可重复运行。
2. 候选抽取不写入 Git。
3. 入库文件无 PII。
4. 新增 overlay 有回归测试。
5. 生成报告 QA 不退化。

### 报告组验收

1. 审核表能看懂，能直接标注通过/修改/不通过。
2. 真实报告抽查中，Part3 不再出现明显固定套话。
3. 药物表和 Part3 内容一致，不出现报告组已指出的错误药物或错配基因。
4. 剩余通用话术有明确清单，而不是隐藏在报告里。

## 14. 风险与对策

| 风险 | 对策 |
|---|---|
| 历史报告存在旧版医学口径 | 候选内容必须报告组审核后入库 |
| 不同 panel 混在同一癌种目录 | 先按文件名产品族分组，再抽取 |
| DOCX 结构不稳定 | 采用 XML 读取 + 容错，不依赖 python-docx 单一路径 |
| PII 泄露 | manifest hash 化，候选表去标识，入库前扫描 |
| 候选文本质量不一 | 分位点级 / 基因级 / 癌种级，低置信度不自动入库 |
| 覆盖率提升但报告不可用 | 必须做人工 UAT，不只看脚本 PASS |
