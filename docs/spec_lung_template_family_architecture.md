# 肺癌模板族自动化建设规格

状态：实施中
最后更新：2026-09-06

## 1. 决策

肺癌产品按“版式族 × PD-L1 变体 × 产品规则包”建设，不为每个基因规格复制一整套
模板，也不把肺癌 588 模板硬套到所有产品。

版式层冻结为六个逻辑模板：

| 版式族 | 无 PD-L1 | 含 PD-L1 |
|---|---|---|
| 小 Panel 基础版 | 独立模板 | 独立模板 |
| 小 Panel 扩展版 | 独立模板 | 独立模板 |
| 大 Panel 综合版 | 独立模板 | 独立模板 |

PD-L1 不是“隐藏或删除一章”的开关。历史终版中的章节骨架、结果摘要和后续章节语义
会随 PD-L1 发生变化，因此必须保留显式模板变体。每个具体产品继续拥有独立的
`panel.yaml`、输入契约、规则、知识覆盖和发布状态；多个产品只复用经过验收的版式模板
与通用处理器。

产品到版式族的归属必须由同产品终版 Word 和真实输入验证。13/62/329/588 是优先
验证规格；20/66/158 需用补充病例确认同族假设；9 基因当前保持待定，不以单份历史
报告直接定族。

## 2. “可生成评审稿”和“可生产发布”分开

目标流程是先产出可读 Word，交给报告组逐份反馈，再依据反馈优化。因此：

- 已建立输入契约、能安全解析的病例，即使缺可选临床字段，也可生成带明确“待补充”
  标识的报告组评审稿。
- 未经审核的医学知识不进入患者级结论；可将对应模块显式标为未启用，但不应因此阻止
  其它已验证章节生成评审 Word。
- 无法确认产品身份、缺少最小源 Excel 结构或会把一个病例的 PD-L1 数据复制给另一病例
  时，不得伪造结果。这些问题必须先由输入材料解决。
- `draft_generation_eligible` 与 `production_eligible` 是两个结论。工程稿通过机器 QA 不等于
  报告组完成医学审核，也不等于可部署为正式产品。

## 3. 当前材料与第 0 步

本地忽略目录中的肺癌台账记录 487 份历史终版报告；同病例源 Excel 配套率仍不足以支撑
六个模板的变量化和双病例验收。技术老师资料索要清单位于：

```text
.work/lung_excel_request_list.tsv
```

清单当前冻结为 36 个唯一样本，字段包括优先级、目标版式、规格、PD-L1 状态、样本号、
需索要材料和理由。版本库只保存校验器，不保存这份含样本号的清单或历史文件名：

```bash
python scripts/validate_lung_excel_request_list.py \
  .work/lung_excel_request_list.tsv \
  --inventory .work/lung_487_family_spec_ledger.tsv \
  --expected-count 36
```

校验必须满足：36 行、36 个唯一样本、Y/N 标志合法、每项可回查到 487 份台账、且没有
索要已登记配套 Excel 的病例。台账里的同一样本多份历史终版不自动删除；资料索要清单
按样本去重，避免重复向技术老师索要。

## 4. 技术老师需要提供的内容

技术老师只需完成资料与审核结论，不需要手工维护代码清单：

1. 按 `.work/lung_excel_request_list.tsv` 提供源 NGS Excel，并确认其对应的同病例历史终版
   Word；若同一样本有多个终版，标明报告组认可的正式版本。
2. 含 PD-L1 的病例同时提供逐病例来源包：TPS/CPS/结果判定、标本编号、检测日期、病例
   专属图片，以及抗体克隆、染色平台和显色系统；原始记录确实没有的字段明确写“未提供”。
3. 每个版式族确认一份母版候选，并在变量化后的第二病例评审稿上给出
   `decision / reviewer / date / P0`。
4. 对 20/66/158 和 9 基因的版式归属给出确认或退回意见。

其中前两项是模板变量化和同案对照的输入，第三项是生产发布证据。报告组签署不是生成
第一版工程稿的前置条件，但没有签署不能把模板状态提升为 `active`。

## 5. 工程实施顺序

1. 冻结 Git/部署版本身份和回滚点。
2. 校验 487 份库存与 36 份资料索要清单的唯一性、配套状态和隐私边界。
3. 为全部已声明模板建立 PHI-safe 源模板样式基线矩阵；有确定性 golden case 的模板
   继续保留渲染后样式基线。
4. 每收到一个同案 Word + Excel，执行 seed → variableize，建立输入、模板和字段来源契约。
5. 用另一真实病例做硬编码泄漏、缺字段、事件边界、章节语义和 Linux LibreOffice 视觉 QA。
6. 生成评审 Word，报告组逐文件反馈；修复后重跑受影响回归。
7. 通过报告组 UAT、Windows Word/WPS 和 Linux 验收后，才合并主线并按精确提交发布。

当前第 1-3 步可独立实施；第 4 步开始按收到的配套病例逐族推进，不要求 36 份全部到齐
才开工。优先完成已有同案输入最多、最接近正式 UAT 的肺癌 588，再推进覆盖量最大的
小 Panel 产品族。

## 6. 2026-09-06 派生输入 draft 授权与验收

用户授权用真实肺癌 552 基因超集 Excel 按产品基因集合派生工程输入，先建设
`lung_13`、`lung_62`、`lung_62_pdl1` draft；同时补齐 `lung_588` 无 PD-L1 变体。
母版从 487 台账按 SHA 追溯，先清洗再变量化，不从 CRC 母版新写肺癌报告。

- 派生只更换 Variations / Hereditary_tumor 的 `ExistInsmall<N>` 旗标，集合内为 1、
  其余空；保留分级与其余全部数据、工作表和 Cnv 的 `ExistIn137`。
- 成员旗标不等于变异分级。C 例 13 基因变异表应为 BRAF V600E、ERBB2 G660D、
  TP53 G245D、PIK3CA A1066V 四行；靶向提示为 BRAF、ERBB2、PIK3CA 三行。
  没有为凑行数而排除 PIK3CA 的业务规则。
- 62 与 62+PD-L1 共用 `ExistIn552 + ExistInsmall62`；588 两变体共用
  `ExistIn552 + ExistInsmall588`。结构识别 NGS 家族，默认无 PD-L1；受信项目/订单
  或网页下拉可选同族含 PD-L1 变体。填写 PD-L1 结果/来源字段自动选择同族含 PD-L1
  产品，不以文件名或虚构的 Excel 列确定免疫组化订单，不允许跨 NGS 产品覆盖。
- 62+PD-L1 复用 `legacy_unspecified_ihc_transcription_v1`，未知字段明确缺失。
  批量表单不得跨病例共享 PD-L1 数值、来源或图片。
- 保留 #13 CNV 误读修复；#14/#15 保持历史默认展示，见
  `docs/analysis-decisions/lung-chemotherapy-pending-review.md`，不新增医学批准。
- 部署为报告组草稿需 A/B/C × 3 包的真实派生输入、网页批量 3/3、独立 Word 表格
  对照、硬编码扫描、双病例泄漏、Linux LibreOffice 全本无空白/孤行页及 QA 门禁。
  页数参考历史同量级，不通过填充空页凑数。588 无 PD-L1 新变体亦须验收。
- 用户明确允许通过工程验收后部署 draft 供复核，但 `production_eligible` 始终为
  false；真实同案逐字对照、技术老师旗标确认和报告组医学签署仍是后续临床放行条件。

可重复构建配置：`config/lung_draft_template_maps.yaml`。派生输入及全部病例产物留在
忽略目录 `.work/`，工程记录集中于 `audit/lung-small-panel-derived-inputs.codex.md`。
