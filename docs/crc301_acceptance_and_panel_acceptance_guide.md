## 二、结构验收方法与结果

**方法**：取一份**真实 301 终版**（语料库 `各癌种基因报告近年汇总/肠癌/*301基因*`，
本地 PII、不入库）与**合成 crc_301 golden case 生成的报告**，分别提取并对比：
章节标题、关键表（存在性 + 行列）、基因检测列表 `n=`、panel 名。内容因病人不同
会不同，但**结构必须一致**。

**结果**（真实终版 vs 合成生成，全部 ✓ 对齐）：

| 要素 | 真实 301 终版 | 合成 crc_301 |
|---|---|---|
| 1.检测结果小结 | ✓ | ✓ |
| 2.1 基因变异检测结果 / **2.2 其它潜在获益** / **2.3 NCCN** | ✓ | ✓ |
| 3.1 TMB / 3.2 MSI / 3.3 免疫疗效（正/负/超进展）| ✓ | ✓ |
| 4. 临床常用化疗 / 5. 检测结果说明 | ✓ | ✓ |
| 第三部分（基因变异及靶向/免疫药物解析）| ✓ | ✓ |
| 基因检测列表 | ✓ | ✓ |
| 参考文献 | ✓ | ✓ |
| 基因列表规模 | n=301 | **n=301** |

> 注：2.2/2.3 这类 crc 子节常被忽略，此次确认合成 crc_301 也正确产出。

**复现**：本地生成合成 crc_301（`build_crc_301_msi_golden_excel` → `ReportGenerator.
generate(..., project_type="crc_301_msi")`），提取章节/表/`n=`，与任一真实 301 终版
的同项对比（提取逻辑可参考 `reportgen/core/style_baseline.py`）。

## 三、报告团队最后一道签收（内容级，必做）

工具/结构已就绪，差"真实病人数据 + 人工核对"。步骤：

1. 任选一个近期真实 **301（结直肠癌301基因+MSI）** 案例的 **Excel 输入**。
2. 登录 `https://panel.mailuo-report.com.cn`，上传该 Excel，项目类型选 **结直肠癌301基因+MSI**，
   填检测者/审核者，生成报告。
3. 把生成的 docx 与该病人**手里的终版**逐项核对：
   - [ ] 1.小结表的变异、频率、靶向药与终版一致
   - [ ] 2.1 检测结果表/2.2 其它药物/2.3 NCCN 内容一致
   - [ ] 3.1 TMB / 3.2 MSI 结论一致，3.3 免疫基因计数一致
   - [ ] 第三部分各基因解析、参考文献覆盖到位
   - [ ] 检测者/审核者签名图正确（需先在签名库登记，见记忆 signature-system）
   - [ ] 目录页码、版式无明显错位
4. 有出入则记录差异截图反馈；无出入即 crc_301 正式签收。

> 大概率无问题（结构已证同构、引擎级修复全继承）。

## 四、未来癌种 panel 通用验收清单

每接一个新 panel，按此清单验收（顺序即工作顺序）：

1. **结构同构**：取该癌种 1~3 份真实终版，与合成生成对比章节/表/基因数/panel 名——
   章节缺失或多余即模板/桥接有问题（异构 panel 如肺 PD-L1 在此暴露差异）。
2. **合成 golden case 绿**：`pytest -k <panel>`，QA=PASS。
3. **金标样式基线**：为该 panel 建 `baselines/<panel>_style_baseline.json`，
   `test_style_baseline.py` 纳入该 panel；以后改后处理一跑即知是否弄坏其样式。
4. **真实样本签收**：报告团队用真实 Excel 跑一份，逐字核对终版（第三节同款清单）。
5. **部署**：合 main → iyun62 ff-only 同步 → 重启（见记忆 prod-restart-procedure）。

**判型**：MSI 类（CRC 表亲）走第 1~5 步很顺；PD-L1/异构类需先补 panel 专属渲染
逻辑（见 [panel-migration-status 记忆] 与 lung C-beta），再走验收。
