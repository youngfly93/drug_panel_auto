# 肺癌小 Panel 产品线建设规格（13 基因 → 62 基因系列）

## 1. 决策与边界

建设顺序固定为：

1. 肺癌 13 基因；
2. 肺癌 62 基因；
3. 肺癌 62 基因 + PD-L1。

这些产品属于“小靶向 Panel 模板族”，不能直接把 CRC358/肺癌329 的大
Panel 模板改个标题后上线。当前阶段只建立脱敏、可追溯的产品入口和建设
门禁；没有真实输入契约和同病例金标准时，不生成“看似可用”的生产模板。

## 3. 13 基因最小输入包

在开始变量化模板前，必须同时具备：

- 报告组选定的正式终版 Word 1 份；
- 与该 Word 完全同病例的源 Excel 1 份；
- 另一份不同病例的真实 13 基因 Excel，专门用于防硬编码泄漏测试；
- 该产品真实 membership 字段、SNV/CNV/融合支持范围及筛选口径；
- 若病例资料不在 Excel 内，提供可冻结的脱敏临床字段快照。

历史 Word 数量多不能替代源 Excel。只有 Word 没有输入，无法证明变异筛选、
计数、排序、药物命中和章节联动是数据驱动的。

## 4. 变量化合同

正式金标准到位后，按以下层次原位变量化：

- 固定层：检测方法、局限性、附录和经报告组确认的肺癌固定知识；
- 标量层：病例资料、日期、质控值、报告编号和结果计数；
- 动态表层：变异、靶向用药、CNV、融合等可变行；
- 富文本层：逐变异解析使用 marker 注入，不保留种子病例静态段落。

模板必须通过种子字面量扫描、第二病例泄漏测试、缺知识强提示、无残留标签、
生产同款 Linux LibreOffice 视觉 QA 和历史差异门禁。

## 5. 医学和数据边界

- 肺癌药物规则按“癌种 + 事件/位点 + 变异类型 + 证据等级”命中；
- 不继承 CRC 抗 EGFR 等跨癌种用药结论；
- 未命中知识不得静默漏掉，必须进入 QA 警告或阻断；
- 62+PD-L1 的克隆、平台、TPS/CPS、结果和来源必须逐病例提供；
- 不带 PD-L1 的 62 基因产品不得因固定附录文字自动生成 PD-L1 结论。

## 6. 发布状态

`lung_13` 当前为 `NOT_BUILT / production_eligible: false`。其聚合库存和阻断
原因记录在 `config/panel_product_readiness/lung_13.yaml`。iyun129 的 Web、
核心生成器和编译前端三层禁用名单必须同时包含该产品；任何环境覆盖试图
提前移除它，部署和 release 切换都会在服务器变更前失败。

62 系列在 13 基因输入合同和小 Panel 模板族稳定后再按相同方法登记与建设。
